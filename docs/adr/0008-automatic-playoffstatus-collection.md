# Collect NFL, NBA and MLB PlayoffStatus ratings automatically

On 2026-11-11 the owner decided to delete the manual `POST /api/ratings/refresh` route, the only caller of the NFL, NBA and MLB PlayoffStatus ratings refresh: “Delete it and build an automatic scraper, I have permission to use the data.” Accept that statement as existing authorization to collect and store PlayoffStatus NFL, NBA and MLB standings and postseason pages. No permission request or private correspondence is needed.

A background worker now owns that refresh. It is **on by default**; `PlayoffRatings:PlayoffStatusCollectionEnabled=false` stops it. Each league (`nfl`, `nba`, `mlb`) has one row in `playoffstatus_collection_state`. The worker claims that row before it sends any request, and the claim moves the league's next attempt 24 hours ahead. A league is therefore fetched at most once a day, whether the attempt succeeds, fails or is interrupted. A restart or a second backend instance cannot fetch it again before then. A failed attempt waits for the next daily boundary; there is no retry shortcut. The worker checks the claims every hour, so a fetch starts within an hour of its boundary.

The decision covers **storage only**. It keeps the existing `Source = "playoffstatus"` rows current and does not change how pages, hype scoring or analysis read them. Today nothing reads NFL, NBA or MLB `playoffstatus` rows for qualification, and this decision does not add such a reader. The NFL What-If pages that [ADR 0007](0007-nfl-seeding-stakes.md) uses are a separate collector.

NHL is unchanged. [ADR 0002](0002-nhl-market-only-qualification.md) rejected model-derived NHL qualification forecasts, including PlayoffStatus, because the owner wanted market prices for NHL qualification; that is a modelling decision, not a missing permission, and this decision does not reverse it. The NHL PlayoffStatus model path stays off as [ADR 0003](0003-nhl-moneypuck-qualification-exception.md) requires, and this worker never requests NHL pages. ADR 0002's bar on treating public readability as authorization still holds: authorization here is the owner's statement, not the site's availability.
