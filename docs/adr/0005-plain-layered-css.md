# Style the backend with plain layered CSS

On 2026-11-07 the owner approved removing Tailwind CSS from the backend. Tailwind 4 compiled `apps/backend/Styles/global.css` into the committed `wwwroot/css/global.css`, and the F# renderers and the race leaderboard web component carried long utility strings. Every visual change needed a Bun install and a CSS build, the class strings duplicated the same card, badge and panel styling across renderers, and tests asserted utility names that had nothing to do with behavior.

The backend now serves hand-written CSS from `apps/backend/wwwroot/css` with no build step and no styling dependency. One `@layer theme, base, components;` declaration orders the cascade: design tokens are custom properties in `theme`, a Preflight-equivalent reset and the page-wide element rules are in `base`, and semantic classes are in `components`. Markup uses semantic class names, with state expressed as modifier classes such as `is-live` and the `hidden` attribute instead of utility toggles. The migration was mechanical and pixel-verified against the Tailwind build, so the rendered pages did not change. [Styling](../styling.md) describes the conventions.
