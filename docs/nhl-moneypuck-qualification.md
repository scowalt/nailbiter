# NHL MoneyPuck qualification runbook

## Status and scope

The collector implements the narrow user-approved [ADR 0003](adr/0003-nhl-moneypuck-qualification-exception.md) exception. **Application defaults remain off. Following the owner's 2026-11-03 “use forecast ON” instruction, production Compose defaults both qualification refresh and fallback selection on for season 2027.** Either has an independent operator stop. Configuration is not evidence of live-source conformance or usable coverage, and changing source does not deploy it. Existing approval is accepted; do not request another credential, permission message or private correspondence. No denial reset, provider probe, production repair, destructive migration or backfill is authorized by this setting. No new source is authorized; PlayoffStatus, Polymarket, paid feeds and unrelated models remain rejected.

MoneyPuck supplies an unconditional **model-derived probability of making the playoffs**, not championship chances, conditional game-result odds, market prices, a seeding certificate or a confirmed outcome. Its rankings remain a separate team-strength input. Hype formulas and Kalshi safeguards are unchanged; missing current qualification is unavailable, never zero. An applicable complete last-known-good hype tuple may remain displayed during age/transport/coverage gaps without authorizing new model selection or collection. Otherwise valid quality and expected closeness remain independently visible. See [continuity verification](testing/pro-hype-continuity.md).

## Controls and normal refresh

`PlayoffRatings` in `apps/backend/appsettings.json` and `PlayoffRatingsOptions`:

| Control | Default | Meaning |
| --- | --- | --- |
| `MoneyPuckRefreshEnabled` | `false` | Permit collection only for explicitly approved, hard-supported NHL season |
| `MoneyPuckSelectionEnabled` | `false` | Permit fallback selection from validated stored evidence |
| `MoneyPuckApprovedSeasons` | `[]` | Explicit allowlist; initial implementation supports **2027 only** (2026–27) |

Both switches independently require exact NHL sport and explicit season 2027 inclusion. Allowlisting 2028 does not support it. Shadow collection does not require selection enabled. Turning selection off immediately removes model eligibility without deleting diagnostic evidence; turning refresh off prevents new qualification collection. Existing rankings remain a separate input, but share the provider-wide daily collection budget. Production Compose defaults refresh=true, selection=true and approved seasons=[2027]. `MONEYPUCK_REFRESH_ENABLED=false` stops qualification collection independently of rankings; `MONEYPUCK_SELECTION_ENABLED=false` stops forecast selection without changing collection or the season. Other hosts retain application defaults. Reconcile actual production settings only under approved rollout scope. Turning selection on considers only eligible stored evidence, never fetches data, and does not shorten refusal backoff or relax the readiness requirements below. New switches never authorize legacy `NhlModelMode`, `NhlModelRefreshEnabled` or `ApprovedSeasons`; either new switch enabled suppresses legacy NHL model selection/refresh even under adverse legacy settings. Do not enable PlayoffStatus separately.

On **2026-10-12**, the user reaffirmed existing approval with **at most one scrape per day**, covering **all MoneyPuck collection**, not qualification alone. This supersedes the frozen specification's synthesized six-hour default. Enforce a **24-hour minimum between admitted attempts**, including failures/cancellation, rather than a calendar-day reset. Publication age must still be **strictly less than 36 hours**; exactly 36 hours is expired. Retrieval cadence does not renew publication freshness or authorize stale data. Respect any tighter applicable access limit; never increase polling to fill gaps.

`MoneyPuckService.RefreshNhlAsync` owns one coordinated cycle: opt-in qualification, then rankings, with separately validated and persisted evidence. The existing ranking refresh and `MoneyPuckQualificationService.RefreshNhlRatingsAsync`/`RefreshNhlRatingsForSeasonAsync` delegate to this owner. `MoneyPuckRefreshBackgroundService` runs at startup and waits until the persisted next-attempt boundary; the general 06:00 UTC ranking worker no longer collects MoneyPuck. The worker is the only production caller; the former `POST /api/ratings/refresh` route is removed. The worker runs only with normal scraper enablement. A disabled/unapproved qualification call returns zero without collecting either input; normal ranking/all-input calls still collect rankings without forecast requests when qualification is off. In-flight, cooldown, blocked or unavailable-admission-storage attempts issue no provider requests. Pages never refresh providers.

Apply additive, repeatable migration `033_MoneyPuckDailyRefresh.sql` before the code. Its singleton `moneypuck_refresh_state` atomically admits at most one backend instance and persists the next allowed UTC instant in full-precision .NET ticks, so PostgreSQL microsecond truncation cannot shorten the daily interval. Restart, simultaneous backend instances, manual calls, startup and background calls do not replenish the budget. Admission marks the cycle active before HTTP; normal successful completion clears active without moving the next-attempt time. A refusal extends the next attempt to its backoff deadline. A crash or failed finalization leaves the cycle active and blocked pending operational review; refusal expiry does not release an active cycle. Migration replay does not reset the daily budget or rewrite source evidence.

Apply additive, repeatable `036_MoneyPuckRefusalExpiry.sql` before the updated collector. It adds nullable `denied_until_ticks`, preserving full .NET tick precision. Legacy `denied=true` records have no trustworthy refusal timestamp, so the first migration assigns a conservative deadline 24 hours from migration time. It preserves `active` and `next_attempt_at_ticks`; later replays leave an assigned deadline untouched. This prevents an immediate retry on deployment without making legacy refusals permanent. A denied row with no deadline remains fail-closed until this migration is applied. No production row deletion or manual reset is required.

**Initial cutover:** this ledger cannot reconstruct failed/cancelled attempts from the old six-hour/in-memory collectors. Under a separately authorized rollout, stop every old MoneyPuck collector and allow at least **24 hours of no MoneyPuck collection before the first new cycle** if the last attempt is not known. Do not run old code alongside the new owner: old collectors do not honor the persisted budget. Subsequent new-code restarts retain the ledger normally.

## Source validation and access boundary

The bounded source contracts implemented offline are:

- [Predictions page](https://moneypuck.com/predictions.htm): content-specific unlinked NHL prediction/playoff-probability heading naming 2026–27 or 2026–2027; navigation, historical links, script/title text and conflicting headings cannot authorize season.
- [Simulations CSV](https://moneypuck.com/moneypuck/simulations/simulations_recent.csv): required `teamCode`, provider-spelled `scenerio`, `madePlayoffs`, `firstSimulatedId`; use only `scenerio=ALL` and `madePlayoffs` directly in [0,1]. Conditional rows and `wonCup`/round fields cannot supply qualification.
- [Publication marker](https://moneypuck.com/moneypuck/simulations/update_date.txt): full offset-aware timestamp before and after all needed data. Both normalized UTC instants must agree and publication <= fetch <= evaluation. Missing/time-only/no-offset/future/regressing clocks reject.
- NHL-owned `/v1/gamecenter/{firstSimulatedId}/landing`: every distinct unconditional-row ID requires exact numeric returned `id` equality and explicit numeric `season=20262027`. No ID prefix, fetch date, July ranking rollover, team participation or game status substitutes for proof. The page label, returned explicit season and game-required end-year season must agree.

Require exactly one unconditional record for each of the **32** recognized canonical NHL teams. Normalize LAK/NJD/SJS/TBL/UTA to LA/NJ/SJ/TB/UTAH. Missing/duplicate/unknown teams, bad required fields, malformed IDs and nonfinite/out-of-range probabilities reject the whole batch. No partial eligible coverage. The source's actual current DOM/CSV shape and exact MoneyPuck-ID linkage are **not empirically established by synthetic fixtures**; see [source notes](nhl-moneypuck-qualification-source-notes.md).

Honest shared client identity: `Nailbiter-MoneyPuck/1.0 (+https://nailbiter.app)`. No same-cycle retries, hedging or automatic redirects for either input. Refusal recovery uses a later normally admitted daily cycle, never an alternate access path. Qualification's serial ceiling remains **4 MoneyPuck GETs + U NHL GETs**, U <= 32: marker, page, CSV, all distinct IDs, marker. Rankings add their own before/CSV/after reads: **7 MoneyPuck GETs + U NHL GETs**, at most **39 total** per admitted cycle; rankings-only collection needs three reads. Structural failures avoid NHL reads. On a bounded successful invalid qualification intermediate body (including oversized/invalid UTF-8), stop remaining qualification data reads but finish its publication bracket: a verified publication race retains prior evidence even when intermediate content is invalid. A bounded invalid ranking CSV also finishes its own publication bracket; a race retains ranking clocks, while matching markers permit ranking invalidation. Denial/transport/cancellation do not continue the bracket.

Limits: either publication marker 4 KiB, page 1 MiB, either CSV 2 MiB, NHL 512 KiB; at most one extra overflow-detection byte, 15-second request deadline, 90-second combined source-work deadline including input persistence. Admission precedes source work; finalization has a separate bounded 10-second storage-only cleanup even after caller cancellation. These are implementation limits, not measured source sizes or provider access grants.

**401/403/429 and recognized access challenges in either input immediately stop all remaining requests and persist a refusal deadline at least 24 hours after the refusal is observed.** On **2026-11-03**, the owner explicitly requested a 24-hour TTL rather than a permanent refusal latch. A valid later HTTP `Retry-After` deadline (date or delay) extends the wait; a shorter or missing hint cannot shorten the day. Challenge text in an oversized bounded prefix is still a refusal, not model invalidation.

At or after the deadline, the normal worker/manual entry point may atomically admit **one** new cycle, only if the shared daily budget is also due and no cycle is active. The same client identity, endpoints and validation apply. Another refusal starts another full backoff window. Successful recovery returns to the normal daily budget. Expiry never refreshes stored probabilities or their publication times; the strict 36-hour forecast expiry is independent.

There is no reset endpoint. Inspect `moneypuck_refresh_state` (`active`, `denied`, `denied_until_ticks`, `next_attempt_at_ticks`) rather than treating the boolean alone as a permanent block: the expired flag is cleared atomically when a new attempt wins admission. Restarts and selection toggles neither shorten nor renew the deadline. Interrupted/unfinalized active cycles remain fail-closed pending operational review; do not clear them or reset the budget. Never spoof identities, solve challenges, follow a bypass redirect, relay research tools into production, replay private APIs or use proxies. This implementation is tested offline; it does not authorize extra development probes, forced refreshes or production-state repair.

## Stored evidence and selection

Qualification rows use `Source=moneypuck_qualification`, not ranking source `moneypuck`, and existing nullable `TeamRating` fields. Qualification evidence needs no schema change or historical rewrite; the daily budget uses only the additive operational-state migration above. Accepted/rejected qualification batches replace all 32 canonical provider/season rows in one transaction; cancellation or database failure leaves no partial batch. Qualification writes never mutate power ranks or their publication/fetch clocks. The companion ranking collector can update its own evidence through its actual source responses, independently of qualification acceptance; ranking retrieval cannot renew or revive qualification. Successfully invalid qualification or a publication race can still be followed by the ranking phase. Transport/timeout/denial/cancellation stops the remaining cycle, retaining uncommitted inputs.

The collector writes `PlayoffModelEvidence` version **4**; verified collector-created version **3** estimates remain readable without a rewrite. Accepted evidence requires `model_projection`, provider-specific `moneypuck-nhl-qualification-model-v1` policy, verified provider/team/season identities, 32/32 counts, accepted estimate state, common refresh ID, actual publication/fetch times and complete `MoneyPuckSeasonProof`. That proof retains content page label/reference/observation, the row's ID, and the deduplicated snapshot-wide exact NHL ID/season/reference/observation set. Readers revalidate persisted evidence; a bare scalar, legacy envelope, forged final flag or boolean-only season claim is not sufficient. Diagnostics stay server-side.

PostgreSQL scalar timestamps retain microseconds; JSON retains full .NET ticks. Only matching JSON/scalar fetch identity compares microsecond buckets, truncating rather than rounding. Publication/fetch/evaluation ordering and publication expiry keep full precision. Downloading unchanged accepted data preserves original fetch/proof clocks and never renews expiry. Changed probabilities or IDs under the same marker reject inconsistent publication.

Transport/timeout/denial and verified publication races retain previous values and all clocks, which still expire normally for current qualification and new calculations. An applicable saved whole hype tuple has no age expiry and cannot renew clocks or bypass source authorization, daily admission or an unexpired refusal backoff. A fully validated publication whose only failure is age still clears current scalar/verification eligibility; its internal `MoneyPuckExpiredProbability` and exact season proof retain structured facts, not selection permission. Malformed/missing/nonfinite data, same-marker corrections and known rejection history take precedence over age. Prior envelopes without these facts cannot claim validated age-only collection. Successfully retrieved invalid snapshots atomically store unavailable state and rejection reason for all teams, revoking fallback. A later successful retrieval of the same rejected publication cannot resurrect it; recovery requires a newer valid publication. Version 4 keeps the supplied `PublishedAt` diagnostic separate from `PublicationBoundary`, the monotonic boundary of agreeing, UTC, clock-valid publications. A newly validated clock advances the boundary even when the snapshot content is rejected; missing, malformed, future or otherwise unverified clocks never advance it. An already known rejected marker does not advance the boundary when time catches up to it. Regression retains the trusted boundary and the actual rejected source timestamp separately. A rejected marker is also barred from same-marker resurrection, without treating a future marker as a high-water value. A complete genuinely current publication newer than the trusted boundary can recover even if earlier than the rejected future diagnostic. Strict 36-hour expiry still uses the selected source publication, not the boundary or download time.

The additive version-4 `MoneyPuckRejectedPublications` array retains exact UTC rejected marker identities independently of both the latest raw diagnostic and the trusted boundary. Missing/no-offset markers, replacement future markers and valid recovery before a rejected future time cannot erase those identities. A subsequent complete response with a known rejected identity atomically persists unavailable state for all 32 teams (`rejected_publication`), rather than preserving an intervening accepted estimate. Readers also exclude a v4 estimate whose publication appears in this array. Known future markers are equality exclusions, never a high-water veto on earlier genuinely current publications.

The array is deduplicated; identities at or below the independently validated boundary are compacted away because existing regression and unavailable-boundary checks already exclude them. Outstanding identities above that boundary are not arbitrarily truncated or replaced by the latest invalid marker: dropping one could permit resurrection. Prior v3/v4 envelopes without this additive field default to an empty array; a still-present rejected raw UTC timestamp seeds the retained identities on the next ordinary refresh. There is no backfill or invented missing raw clock/history. An identity already erased by older software cannot be reconstructed from a missing marker. Verified prior estimates retain read compatibility; legacy authorization is unchanged.

Version 3 boundary fallback requires collector identity/policy/refresh metadata, matching scalar fetch identity and UTC publication <= fetch <= evaluation. Ambiguous `invalid_publication` and `future_observation` records cannot supply a boundary, and a future diagnostic is never promoted. Version 3 has no separate retained boundary to reconstruct when its clock is unverified. Legacy version 2/bare/unverified model records remain ineligible; neither fallback nor version 4 relaxes persisted season/team/proof checks.

Selection is independent per team:

1. Eligible Kalshi (including trusted verified final qualification outcomes) wins, even against newer MoneyPuck.
2. A trusted Kalshi qualification-resolution block vetoes fallback.
3. Only an explicitly enabled/allowlisted, fully eligible MoneyPuck estimate may fill missing/rejected/expired Kalshi.
4. Otherwise qualification remains unavailable.

Never blend probabilities. Enforce the shared 25-point Kalshi qualification spread limit, widened from 20 points at the user's request on 2026-10-13; identity, depth, freshness and resolution safeguards are unchanged. MoneyPuck **0 or 1 is still nonfinal** (`MoneyPuckModel`), not clinched/missed playoffs. Turning selection off restores default Kalshi-only behavior without deleting evidence. Non-NHL source-selection policies are unchanged. Valid qualification cannot override missing competition/progress, ranking or pregame game-winner evidence; total hype still requires all independent inputs and an upcoming unstarted game.
